# Stage Zero

Мобильный тренажёр выступлений. Каркас на Expo SDK 57, TypeScript и expo-router. Собран базовый проход раунда для тестов — что готово, а что нет, см. ниже. ТЗ — в `docs/tz/`.

Камера, микрофон и детектор лица — нативные модули. Expo Go их не запускает, нужен development build.

Нужен Node `>= 22.13` (в репозитории `.nvmrc` — 24). На 22.12 React Native 0.86 не ставится.

## Старт

```sh
nvm use
npm install
cp .env.example .env
npx expo prebuild
npm run ios
# или
npm run android
```

`npm start` поднимает Metro для уже установленного development build.

`ios/` и `android/` генерирует `npx expo prebuild`, в git они не коммитятся.

Детектор лица на симуляторе iOS 26 не заводится: у ML Kit нет ARM64-среза. Проверять на устройстве.

## Запуск с бэкендом

Поднять бэкенд (репозиторий `backend`, по умолчанию порт 8000), затем:

```sh
npm install
cp .env.example .env   # EXPO_PUBLIC_API_URL=http://localhost:8000, моки выключены
npm run web
```

Если адрес бэкенда задан, приложение ходит в реальный API. На телефоне `localhost` не подойдёт — нужен HTTPS-адрес туннеля. Без ключей AI бэкенд запускается с `AI_MOCK=1`: `/api/ai/*` отвечает примерами, а игровая часть (темы, раунды, звание, лидерборд) настоящая.

## Тест без бэкенда

Без `.env` (или с `EXPO_PUBLIC_USE_MOCKS=1`) приложение работает на локальных моках из `src/api/mocks.ts`. На моках питч можно закончить через 5 секунд, а реакции зала имитируются по таймеру.

## Что уже есть

Вход по нику → меню (звание, тема дня, лидерборд) → колесо → подготовка с таймером и заметками → сцена (шкала внимания, зал и жюри на эмодзи, запись звука в файл) → вопросы жюри с записью ответа → разбор.

Чего ещё нет: камера и взгляд, живой поток PCM в `WS /api/ai/live` (на реальном API зал реагирует только на «15 секунд без ошибок»), разминка «Представься залу», свой питч, тап по маркеру в разборе. `AudienceStage` и `JuryTable` в `src/ui/` — заглушки до компонентов универсала.

## Окружение

| Переменная | Зачем |
| --- | --- |
| `EXPO_PUBLIC_API_URL` | HTTPS-адрес бэкенда |
| `EXPO_PUBLIC_USE_MOCKS` | `1` — моки, `0` — реальный API |
| `APPLE_TEAM_ID` | Team ID для подписи iOS-сборки, свой у каждого |

`EXPO_PUBLIC_*` читаются в `src/config/env.ts`, `APPLE_TEAM_ID` — в `app.config.js`.

## Структура

Одна кодовая база на Expo: на компьютере это сайт (`npm run web`), на телефоне — приложение. Вёрстка переключается по ширине окна (`src/hooks/useLayout.ts`): от 900 px — раскладка сайта, уже — телефонная.

| Папка | Что там |
| --- | --- |
| `app/` | экраны: лендинг (`index.tsx`), вкладки `(tabs)/` — меню и профиль, поверх них раунд: колесо, подготовка, свой питч, сцена, жюри, разбор |
| `src/design/` | палитра, шрифты, контур и тень |
| `src/ui/` | кнопки, карточки, шапка, док вкладок (`Dock.tsx`) и детали макета: билет, печать, гирлянда, колесо, таблички; `Backdrop.tsx` — фон страниц (лучи софитов, рисунки, силуэты зала) |
| `src/scene/` | зал: слои сцены, зрители, жюри, рамка камеры; `assets.ts` и `layout.ts` сгенерированы |
| `src/audio/` | запись, проигрывание, живой поток звука в `WS /api/ai/live` |
| `src/api/`, `src/store/`, `src/content/` | запросы к бэкенду и моки, состояние раунда, тексты про аудитории |

Шкала внимания на сцене (`app/stage.tsx`) показывает, что зал думает о последних секундах, и ничего не копит. Она складывается из трёх частей: голос (сам по себе поднимает шкалу только до 60), содержание (сервер раз в ~7 секунд оценивает, по теме ли и по делу ли последние слова: до ±35) и оговорки (паразит и темп снимают баллы на 20 секунд, тишина дольше 3 секунд и взгляд мимо зала — пока длятся). Без сервера (моки, приложение) оценки содержания нет, и шкала выше 60 не поднимается.

Подсказки на сцене: под таймером появляется короткая строка — слово-паразит, темп, тишина, подсказка по содержанию от сервера («Back to your favourite food», «Good example»). Несколько подряд показываются по очереди.

Зрители живые: стоя чуть «дышат» (каждый в своём ритме), а при смене настроения коротко подпрыгивают — переход видно сразу. Ступени реакции (`src/scene/AudienceScene.tsx`), шкала 0–100, старт с 50: ниже 47 — двое отвлеклись, ниже 38 — пятеро, ниже 28 — почти все в телефонах; выше 53 — двое удивлены, выше 70 — пятеро, выше 85 — почти все.

Видео и взгляд (`src/video/`): в браузере `capture.web.ts` пишет видео с камеры в H.264 (запасной вариант — VP8) с ключевым кадром раз в секунду; запись остаётся во вкладке. В разборе видео играет со своим звуком и само ведёт ползунок и маркеры (`PitchVideo.web.tsx`); без видео играет звукозапись (`PitchPlayer.tsx`). Камеру можно переключить кнопкой на рамке, если у устройства их больше одной; после переключения видео в разборе начинается с этого момента. Взгляд в браузере не измеряется. В приложении `capture.ts` — заглушка: взгляд должен давать детектор лица на ML Kit (`react-native-vision-camera-face-detector`) через `onLook` и список `gaze`.

Навигация: лендинг (`app/index.tsx`) видят только те, кто ещё не вошёл — вошедшего он сразу отправляет на вкладки. Вкладок две, «Главная» (меню режимов) и «Профиль» (`app/(tabs)/`): в приложении это системная панель вкладок (`expo-router/unstable-native-tabs`) — на iOS 26 жидкое стекло, которое прячется при прокрутке, на Android — Material-панель; на сайте на телефоне — свой стеклянный док внизу (`src/ui/Dock.tsx`, учитывает нижнюю панель Safari и полоску «домой»: `viewport-fit=cover` в `public/index.html`), а на компьютере вкладки стоят по центру шапки: «Главная» и профиль под ником игрока — единственная кнопка аккаунта. Раунд — колесо, подготовка, свой питч, сцена, жюри, разбор — открывается поверх вкладок, дока там нет, чтобы не отвлекать. Выход из аккаунта — внизу профиля.

Шапка (`src/ui/AppHeader.tsx`) одна на все экраны, кроме сцены, и везде одинаковая: стеклянная, прилипает к верху; слева место под «назад» (есть всегда, занято или пустое — логотип не прыгает), затем логотип, справа язык и не больше одной кнопки экрана («Войти» на лендинге). Выбор языка (`src/ui/LangSwitch.tsx`) в приложении системный: лист действий на iOS, диалог на Android; в браузере — меню под кнопкой.

Вход и профиль: вход по почте и паролю, при регистрации — ник и код из письма (`app/index.tsx`); в браузере есть ещё кнопка Google (`src/auth/GoogleButton.web.tsx`) — она появляется, когда на сервере задан `GOOGLE_CLIENT_ID`, в приложении её пока нет; токен хранится в `src/store/game.ts` и уходит с каждым запросом (`src/api/client.ts`). Вход помнится между запусками: на сайте — в localStorage, в приложении — файлом в папке документов (`src/store/session.ts`, через expo-file-system, как и язык). Профиль (`app/(tabs)/profile.tsx`) — трекер прогресса и история всех питчей; раунд из истории открывается в разборе без записи.

Разбор (`app/result.tsx`): у транскрипта свой плеер во всю ширину карточки (`src/ui/Transcript.tsx`), на его дорожке — отметки текста, а слово, которое звучит сейчас, подсвечено; нажатие на слово перематывает запись. Видео показывается только на телефоне (узкий экран) и со своей дорожкой, на которой только моменты взгляда мимо зала; на компьютере видео не пишется и не показывается.

Свой питч (`app/own.tsx`): можно загрузить презентацию (PDF или PPTX) и разложить текст по слайдам; слайд про демо превращается в «Demo time.». Темп (спокойный, обычный, быстрый) выбирается на подготовке (`app/prep.tsx`). Кнопка «Present with slides» показывает слайды PDF на сцене в маленькой рамке рядом с камерой (`src/ui/SlideFrame.tsx`): листаются стрелками ← → и кнопками под слайдом. Страницы PDF рисуются в браузере через pdf.js (`src/slides/render.web.ts`), файл никуда не уходит; в приложении и для PPTX показа пока нет.

Уровень сложности (`src/ui/LevelPicker.tsx`) выбирается в меню или на колесе и относится ко всему раунду: от него зависят тема, время на подготовку, строгость разбора и жюри (это делает сервер) и характер зала на сцене — на тяжёлом оговорки стоят в 1,6 раза дороже, тишина замечается через 2 секунды вместо 4, а впечатляет зал только содержание с оценкой выше 60 (таблица `ROOM` в `app/stage.tsx`). На подготовке уровень показан и уже не меняется.

В разборе (`app/result.tsx`) все ошибки отмечены прямо в тексте: бэкенд отдаёт у каждого события `start`/`end` — место в расшифровке. Кроме паразитов, повторов, пауз, темпа и ругани бэкенд теперь отмечает запинки (`stumble` — оборванное и начатое заново слово), неуверенные фразы (`weak_phrase` — смягчения вроде «мне кажется», извинения на сцене, вялое начало и слабый финал) и затухающий к концу фразы голос (`energy`); у каждого типа свой цвет (`src/design/theme.ts`), легенда показывает только то, что встретилось. Карточка «Главное» (`src/ui/Highlights.tsx`) собирает из цифр разбора две колонки — что получилось и что поправить: паразиты, темп, паузы, запинки, неуверенность, монотонность и затухание голоса, взгляд, время и самые сильные и слабые критерии содержания; на телефоне она и три совета стоят до записи и расшифровки.

В браузере работают камера в рамке и живой поток звука. В приложении для них пока стоят заглушки (`CameraFrame.tsx`, `live.ts`): нужны `react-native-vision-camera` и `@siteed/audio-studio`.
