# Stage Zero

Мобильный тренажёр выступлений. Каркас на Expo SDK 57, TypeScript и expo-router. Собран базовый проход раунда для тестов — что готово, а что нет, см. ниже. ТЗ — в `docs/tz/`.

Камера, микрофон и детектор лица — нативные модули. Expo Go их не запускает, нужен development build.

Нужен Node `>= 22.13` (в репозитории `.nvmrc` — 24). На 22.12 React Native 0.86 не ставится.

## Старт

```sh
nvm use
npm install
cp .env.example .env
npx expo prebuild
npm run ios
# или
npm run android
```

`npm start` поднимает Metro для уже установленного development build.

`ios/` и `android/` генерирует `npx expo prebuild`, в git они не коммитятся.

Детектор лица на симуляторе iOS 26 не заводится: у ML Kit нет ARM64-среза. Проверять на устройстве.

## Запуск с бэкендом

Поднять бэкенд (репозиторий `backend`, по умолчанию порт 8000), затем:

```sh
npm install
cp .env.example .env   # EXPO_PUBLIC_API_URL=http://localhost:8000, моки выключены
npm run web
```

Если адрес бэкенда задан, приложение ходит в реальный API. На телефоне `localhost` не подойдёт — нужен HTTPS-адрес туннеля. Без ключей AI бэкенд запускается с `AI_MOCK=1`: `/api/ai/*` отвечает примерами, а игровая часть (темы, раунды, звание, лидерборд) настоящая.

## Тест без бэкенда

Без `.env` (или с `EXPO_PUBLIC_USE_MOCKS=1`) приложение работает на локальных моках из `src/api/mocks.ts`. На моках питч можно закончить через 5 секунд, а реакции зала имитируются по таймеру.

## Что уже есть

Вход по нику → меню (звание, тема дня, лидерборд) → колесо → подготовка с таймером и заметками → сцена (шкала внимания, зал и жюри на эмодзи, запись звука в файл) → вопросы жюри с записью ответа → разбор.

Чего ещё нет: камера и взгляд, живой поток PCM в `WS /api/ai/live` (на реальном API зал реагирует только на «15 секунд без ошибок»), разминка «Представься залу», свой питч, тап по маркеру в разборе, сохранение ника между запусками. `AudienceStage` и `JuryTable` в `src/ui/` — заглушки до компонентов универсала.

## Окружение

| Переменная | Зачем |
| --- | --- |
| `EXPO_PUBLIC_API_URL` | HTTPS-адрес бэкенда |
| `EXPO_PUBLIC_USE_MOCKS` | `1` — моки, `0` — реальный API |
| `APPLE_TEAM_ID` | Team ID для подписи iOS-сборки, свой у каждого |

`EXPO_PUBLIC_*` читаются в `src/config/env.ts`, `APPLE_TEAM_ID` — в `app.config.js`.

## Структура

Одна кодовая база на Expo: на компьютере это сайт (`npm run web`), на телефоне — приложение. Вёрстка переключается по ширине окна (`src/hooks/useLayout.ts`): от 900 px — раскладка сайта, уже — телефонная.

| Папка | Что там |
| --- | --- |
| `app/` | экраны: главная, меню, колесо, подготовка, свой питч, сцена, жюри, разбор |
| `src/design/` | палитра, шрифты, контур и тень |
| `src/ui/` | кнопки, карточки, шапка и детали макета: билет, печать, гирлянда, колесо, таблички; `Backdrop.tsx` — фон страниц (лучи софитов, рисунки, силуэты зала) |
| `src/scene/` | зал: слои сцены, зрители, жюри, рамка камеры; `assets.ts` и `layout.ts` сгенерированы |
| `src/audio/` | запись, проигрывание, живой поток звука в `WS /api/ai/live` |
| `src/api/`, `src/store/`, `src/content/` | запросы к бэкенду и моки, состояние раунда, тексты про аудитории |

Зал на сцене (`app/stage.tsx`): пока звучит голос, внимание растёт, после нескольких секунд речи без оговорок — быстрее. Оговорки (паразит, темп) только гасят восторг. Скучать зал начинает от тишины дольше 3 секунд и когда игрок дольше 2 секунд не смотрит в зал. Звучит ли голос, в браузере определяет `live.web.ts` по громкости микрофона, в приложении — уровень записи (`useRecorder.ts`).

Ступени реакции (`src/scene/AudienceScene.tsx`), шкала 0–100, старт с 50: ниже 47 — двое отвлеклись, ниже 38 — пятеро, ниже 28 — почти все в телефонах; выше 53 — двое удивлены, выше 70 — пятеро, выше 85 — почти все.

Видео и взгляд (`src/video/`): в браузере `capture.web.ts` пишет видео с камеры, оно остаётся во вкладке и показывается в разборе рядом с плеером (звук ведёт плеер, видео идёт за ним). Взгляд в браузере не измеряется. В приложении `capture.ts` — заглушка: взгляд должен давать детектор лица на ML Kit (`react-native-vision-camera-face-detector`) через `onLook` и список `gaze`, который уходит на бэкенд вместе с записью.

В разборе (`app/result.tsx`) все ошибки отмечены прямо в тексте: бэкенд отдаёт у каждого события `start`/`end` — место в расшифровке.

В браузере работают камера в рамке и живой поток звука. В приложении для них пока стоят заглушки (`CameraFrame.tsx`, `live.ts`): нужны `react-native-vision-camera` и `@siteed/audio-studio`.
